# iOS client parity tracker

Reference: the iOS source in this repository, including `StreamScreen.swift`, `PortraitStreamScreen.swift`, `StreamClient.swift`, `TrackpadView.swift`, `TextComposition.swift`, `HostSettingsPanel.swift`, and their protocol/test helpers. The installed Mac host in the initial test is Sill 0.6.1; features in the current repository may require a newer host. A check here means code and its specific verification exist, not blanket equivalence.

Product direction: follow the iOS client's layout and interaction by default. Earlier Android-specific picture-trackpad, side-control landscape layout, and automatic text-scale adjustment are being replaced by the original behavior.

The source-based visual inventory is in `IOS_VISUAL_INVENTORY.md`. A first visual pass aligns parts of the toolbar, app drawer, trackpad, tour, connection screen, settings panel and thumbnails. On the Xiaomi saved connection, real QR pairing, grouping, portrait controls, thumbnail selection, landscape toolbar and settings rotation were checked. Real home previews and in-session pairing are not implemented; connection status details, menu presentation, thumbnail animations, symbols and other states still differ. Long-press/drag and full side-by-side visual verification remain outstanding.

## Connection and security

- [ ] Paired mutual TLS, certificate pinning, incorrect/expired codes, identity changes and revocation: core path works on the Xiaomi over Tailscale; remaining error cases need end-to-end checks.
- [ ] Discovery and saved Macs: saved records use verified certificate identity, preserve legacy address pins, and group multiple addresses. On the Xiaomi, a Mac was temporarily placed in a group and restored to ungrouped. Bonjour recognition checks the saved key and still verifies the TLS pin. Signed MacInfo checks the active TLS identity and replay counter; an existing Xiaomi pairing reconnected and received verified MacInfo. Multi-address fallback, address-origin/expiry rules and signed implicit remote-port changes have logic tests; actual network fallback and Bonjour discovery still need device verification. A damaged legacy record can be repaired only after successful pinned TLS for an explicitly entered address; on the Xiaomi the missing home card appeared after such a connection and successfully reconnected. Legacy entries whose original port provenance is unknown remain explicit until re-advertised. QR pairing currently records its initial endpoint as manual even if obtained by discovery.
- [ ] QR/deep-link pairing: Android accepts validated pairing links, embeds the camera scanner in the Add Mac card with explicit identity confirmation, and can try discovered local TLS endpoints for links without addresses. On the Xiaomi a real Mac QR code was scanned, confirmed, paired and connected. Camera denial, background and repeated rotation still need device verification. Local discovery currently tries at most eight endpoints without an explicit address.
- [ ] In-session external pairing: an independent attempt, session/identity guards and a confirmation overlay exist behind a disabled production flag. Isolated Android UI and authorization tests pass; live same-Mac verification is pending. The iOS unpaired local-session and ask/withdraw paths are not implemented.
- [ ] Reconnect and recovery: bounded retry, keyframe recovery, Goodbye reason handling and iOS-style automatic desktop selection for a new session with no source are implemented. On the Xiaomi, two returns restored the original window and a third return after a socket disconnect automatically restored the desktop. A later background-disconnect regression was fixed and the device reconnected through TLS and the first list; picture persistence was not confirmed in that run. Chain migration preserving the previous window is not implemented. Verify Wi-Fi/mobile transitions, Mac sleep/restart, revocation, stalled connections and cancellation; remote-disabled fallback remains conservative.
- [ ] Host locked/off-console state: ordinary lock and other-user states have separate handling, with a cover until a newly decoded frame is presented. Normal streaming was verified on the Xiaomi; lock/unlock and other-user transitions still require real-device verification.

## Windows and picture

- [ ] Window catalog, app icons, app launching, menu and thumbnail commands exist. The application drawer follows iOS app-name search and cycles windows per application; it is anchored over the picture and remains open through rotation. On the Xiaomi, the user confirmed rotation and automated checks verified portrait search, keyboard return and a rotation. Android 10 keyboard insets, window-strip drag behavior, real-time drag animation and full menu state remain to verify or implement.
- [ ] Home Mac previews: policy and an isolated encrypted-cache backend have synthetic tests, but are not connected to real video. On the Xiaomi, the synthetic Keystore probe received system biometric success but the synthetic key was still rejected as unauthenticated, including in the same process; real lock, deletion and crash behavior remain unverified. No real Mac preview is persisted by this implementation yet.
- [ ] Mac menus: versioned state, stale and disabled rows, submenu loading, timeout and notes are implemented; the top-level list opened on the Xiaomi. Nested navigation and late-reply behavior still need device verification, and Android dialogs differ from the iOS system menu.
- [ ] Selected-window fitting: iOS starts with Aa off and fits the complete picture without stretching. On 2026-11-12 the user confirmed Aa changes the picture on the Xiaomi, although App Store showed no visible difference between 1.25 and 1.5. On 2026-11-13 the phone toolbar buttons disappeared from the accessible tree while holding Aa and returned on release. Test repeated source changes, rotation, app minimum sizes and host refusal; some applications cannot fill the picture without cropping.
- [ ] Stage Manager may cause the Mac host to supply a tilted thumbnail. The iOS client displays the host thumbnail; Android follows that behavior. Test window closure, source changes and cache cleanup.
- [ ] Desktop display cycling is implemented only when the host advertises it. The tested Mac 0.6.1 does not; the Android client cannot add the missing host capability.
- [ ] Zoom, pan and gesture ownership: current 1–5× pinch is present. On 2026-11-12 the user confirmed portrait tap and pinch on the Xiaomi; still test the complete finger lifecycle, cancellation, rotation and focal-point preservation against `StreamZoom.swift`.
- [ ] Portrait Larger Picture, soft keyboard accommodation and responsive layouts: iOS portrait geometry is connected. On the Xiaomi the basic portrait controls and drawer keyboard clearance were checked, and the user confirmed the landscape top toolbar and large picture. Larger Picture, rotations and PiP after this geometry change still need device checks. Android 10 cannot currently measure the IME height.

## Input and local interaction

- [ ] Trackpad single/double click, drag, two-finger scroll and right click, scroll momentum, reverse scrolling, three/four-finger gestures and cancel/rotation behavior; never send a click during a pinch. On 2026-11-12 the user confirmed two-finger scrolling and momentum felt smooth without accidental clicks on the Xiaomi. A persistent reverse-scroll setting and capability-gated Mac gestures are implemented; the new direct picture-input path and multi-touch gestures need real-device checks.
- [ ] IME composition, correction, selection, emoji and dictation: Return/Tab fences, cross-fence retyping, stale callback handling and delayed trimming have logic checks. iOS dictation uses its system keyboard to recognize speech and sends text over the existing input protocol; it does not send microphone audio to the Mac. Synthetic Chinese composition and revision tests passed on the Xiaomi's Android InputConnection, and on 2026-11-13 the user confirmed that spoken text appeared on the Mac using the phone keyboard's microphone. Actual voice corrections, dictation across newline, emoji and lifecycle transitions remain to verify. No Sill microphone permission or audio uplink is implied.
- [ ] Physical keyboard: local-dialog focus gating, function keys and capability-gated repeat are implemented with logic checks; verify real keyboards, shortcuts, older hosts and third-party input methods.
- [ ] Mouse and pointer: shape and basic host position exist. Physical mouse hover, left/right buttons and wheel have logic checks; actual hardware event delivery, source/ownership, out-of-frame visibility and reconnect behavior still need verification. The host protocol has no middle-button action.
- [ ] Clipboard: opt-in text sharing, the iOS-style immediate-paste preference, a foreground metadata-only prompt and acknowledgement-before-paste are implemented with logic checks. Clipboard text is read only after a user action. On 2026-11-13 the user enabled sharing and confirmed both the settings action and the floating prompt pasted phone-copied text into a Mac app with feedback. Clipboard echo, slow-network cancellation and background behavior still need verification. Missing or ambiguous metadata suppresses the prompt; same-millisecond changes can be missed and processed metadata is not persisted across app restarts.

## Audio, settings and lifecycle

- [ ] Viewport frame rate follows display capability with a 60 fps cap on remote or power-saving connections; verify dynamic changes on hardware. Android VPN route classification may not identify every split-tunnel route.
- [ ] Sound: AAC-ELD decoding is experimental and off by default. The iOS-derived timing model, decode mapping, output timeline, mute and route logic have Swift differential and simulated-device tests. On the Xiaomi a silent probe decoded 480/512-frame packets with extracted ASC and contiguous PTS. After startup fixes, the real runtime passed four silent synthetic runs with zero reported underruns; the overall comparison probe still deliberately reports failure for the old raw-ESDS/legacy timing controls. Real audio, route changes, reconnect and audible synchronization remain unverified; audio failures must remain isolated from video.
- [ ] Complete host settings and local preferences, with capability gating, host acknowledgements and failure handling; include scrolling, gestures, long-press duration and Larger Picture. Host quality uses a menu, resolution and frame rate use segments, and supported switches appear in the main panel. The Xiaomi showed the new controls through rotation; long-press duration was stepped from 0.5 to 0.6 and restored to 0.5. Host acknowledgement, refusal, timeout and accessibility at large sizes need device verification.
- [ ] Picture in Picture and foreground/background handling: opt-in PiP, pause/resume, timeout and input/viewport/clipboard isolation are implemented. On 2026-11-13 the user confirmed moving video, pause/resume, and normal picture and controls after returning on the Xiaomi. Lock, timeout and isolation still need device verification. Android exits the activity on PiP stop; idle-screen policy and foreground-only clipboard updates also need lifecycle verification.
- [ ] TalkBack, larger fonts, announcements and actions; connection/error/version/slow-network status and first-run guidance. First-run guidance is implemented with accessible actions, persisted progress and input isolation; its first screen and rotation retention were checked on the Xiaomi. Full visual and accessibility parity, and later guidance steps, still need verification.
- [ ] Foldables and external displays: design for Android's own device capabilities after phone functionality is verified; do not claim iPhone Duo-specific behavior is already supported.

## Verification

Every implementation task needs focused logic tests plus a real-device scenario where hardware, OS, input, video or network behavior matters. Record whether a feature is implemented, verified locally, verified on the Xiaomi, or blocked by the installed host. Run `tests/run.sh`, `assembleDebug` and the Android CI workflow after each batch. Do not put pairing codes, screenshots, typed text or clipboard contents in the repository or logs.
